# Security policy

## Supported versions

After the first stable release, the latest 1.x minor release receives security
fixes. Pre-release snapshots and older minors may be asked to upgrade.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting / Security Advisory facility for
this repository when available. If it is not enabled, contact the repository
owners through a private channel listed on the GitHub organization profile and
ask for a confidential reporting route. No project security email is claimed
here because none is configured in the repository.

Include affected versions, impact, reproduction details and any proposed
mitigation. Do not publish a critical, unpatched issue in the public issue
tracker. Maintainers should acknowledge the report, coordinate a fix and
credit/disclose according to the reporter's wishes after users can update.

Never include access tokens, passwords, private signing keys, third-party user
data or live service credentials in a report or test fixture.
